# 🎒 Discord Бот "Бродячий Торговец"

Бот для отслеживания местоположения бродячего торговца в DayZ на серверах Chernarus.

## 📋 Функционал

### Предрегистрация пользователей
- Автоматическая регистрация при первом использовании бота
- Сохранение Discord User ID, username и даты регистрации

### 📍 Где торговец?
- Просмотр текущих сообщений о местоположении торговца на всех 4 серверах (cherno-1, cherno-2, cherno-3, cherno-4)
- Отображение:
  - Названия локации
  - Координат (X, Y)
  - Списка пользователей, сообщивших о торговце (первый выделяется **жирным**)
  - Скриншота локации

### 📢 Сообщить о торговце
Многоступенчатый процесс:
1. Выбор сервера (cherno-1/2/3/4)
2. Выбор локации из списка
3. Если локация имеет несколько зданий (например, Березино-1, Березино-2) — выбор конкретного здания
4. Автоматическая запись с флагом первого сообщившего

### 🔎 Начать поиск / 🗺️ Статус локаций
- В поиске сначала показан прогресс по каждому серверу; после выбора сервера Discord Components V2 выводят компактные строки со статусом и действиями `Не найден`/`Отменить` и `Нашёл`. Фото точки открывается через список внизу страницы.
- До выбора сервера поиск показывает сообщения о торговце по каждому серверу и лидирующую локацию, если сообщения расходятся.
- Точки отсортированы по приоритету: подтверждённый торговец, ещё не проверенные локации, затем проверенные без торговца.
- Игрок может отмечать несколько точек на одном сервере; повторная проверка той же точки обновляет её время
- Сразу после отправки можно отменить свою отметку кнопкой `↩️ Ошибся / вернуться`
- Сводка по серверу показывает 9 точек на странице, время последней проверки и число проверивших игроков
- Подтверждённый торговец имеет приоритет и автоматически снимает отметки «не найден» для той же точки

### 🔄 Автоматическое архивирование
- Ежедневный сброс данных в 04:00 по московскому времени, когда торговец меняет расположение
- Сохранение всех предыдущих записей в архиве для администратора
- Дата последнего сброса хранится в SQLite: пропущенный сброс выполняется при запуске или следующей операции, а перезапуск не очищает новые отметки повторно.

### Подписки на уведомления
- В разделе «Подписки» пользователь выбирает один или несколько игровых серверов.
- Настройки открываются в личном меню Components V2, видимом только пользователю.
- При сохранении непустого списка бот отправляет проверочное личное сообщение. Подписки сохраняются только после успешной отправки.
- Если личные сообщения недоступны, меню объясняет, как разрешить их и разблокировать бота. Кнопка «Проверить снова» сохраняет выбранные серверы для повторной проверки.
- При первой отметке новой локации на выбранном сервере подписчики получают личное сообщение Components V2 с сервером, локацией, координатами и кнопкой «На карте».
- Кнопка «Фото» в уведомлении открывает изображение найденной точки. «Подписки» открывает управление выбранными серверами прямо в личке, где можно отписаться от всех. Обе кнопки работают после перезапуска бота.
- Под координатами указан ник автора первой отметки («Сообщил»), без упоминания. Он сохраняется в очереди на момент отметки; последующие подтверждения не меняют автора и не вызывают новую рассылку.
- Повторные подтверждения той же локации не рассылаются до ежедневного сброса в 04:00 МСК. Разные локации вызывают отдельные уведомления.
- Подписки и очередь уведомлений хранятся в SQLite и переживают перезапуск. Очередь обрабатывается каждые 10 секунд, до 20 сообщений за проход. Временные ошибки повторяются с увеличением интервала до конца текущего периода поиска; закрытая личка одного подписчика не мешает остальным.
- «Отписаться от всех» отключает уведомления без проверки личных сообщений. При ежедневном сбросе подписки сохраняются, а устаревшая очередь очищается.
- Перед отправкой бот повторно проверяет актуальность отметки и подписки. Операции SQLite выполняются вне основного цикла Discord; ошибки базы не останавливают задачу рассылки.
- Для защиты от массовых ложных отметок сменить локацию на одном сервере можно не чаще раза в 60 секунд. Ограничение общее для Discord и карты и сохраняется при перезапуске.
- В списках сообщивших показываются до 10 игроков и число остальных. Длина текста ограничена, чтобы большие списки не ломали меню Discord.

## 🚀 Установка и запуск

### 1. Настройка токена

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env        # Linux/Mac
copy .env.example .env      # Windows
```

Вставьте ваш токен бота Discord в файл `.env`:

```
DISCORD_BOT_TOKEN=ваш_токен_здесь
```

**Как получить токен:**
1. Перейдите на https://discord.com/developers/applications
2. Создайте новое приложение (или выберите существующее)
3. Перейдите в раздел "Bot"
4. Нажмите "Reset Token" и скопируйте токен
5. Включите необходимые Privileged Gateway Intents:
   - ✅ MESSAGE CONTENT INTENT
   - ✅ SERVER MEMBERS INTENT

### 2. Добавление бота на сервер

1. В панели разработчика перейдите в "OAuth2" -> "URL Generator"
2. Выберите scope: `bot`, `applications.commands`
3. Выберите permissions:
   - Send Messages
   - Send Messages in Threads
   - Embed Links
   - Attach Files
   - Read Message History
4. Скопируйте полученную ссылку и перейдите по ней

### 3. Запуск через Docker Compose (рекомендуется)

```bash
# Сборка и запуск
docker compose up -d

# Просмотр логов
docker compose logs -f

# Остановка
docker compose down

# Перезапуск после изменений
docker compose up -d --build
```

### Запуск без Docker

```bash
pip install -r requirements.txt
python main.py
```

## 🎮 Использование

После запуска бота используйте команду `!start` или `/menu` для вызова главного меню с кнопками:

- **Начать поиск** / **Где торговец?**
- **Подписки** / **Справка**
- **Добавить себе или поделиться**

Статистика проверенных точек показывается в разделе «Начать поиск». Раздел «Где торговец?» сразу выводит подробности по всем серверам.

Главное меню продолжает работать после пересборки и перезапуска бота: повторно вызывать `!start` не требуется. Временные окна поиска и подписок не восстанавливают несохранённый выбор; нажатие в устаревшем окне открывает рабочее личное главное меню. Во время остановки контейнера бот отвечать не может — нажмите кнопку после его запуска.

## 🗄️ База данных

### Список Discord-серверов в логах

При запуске и повторном событии готовности после подключения бот выводит число
Discord-серверов, где он установлен, и сведения по каждому: название, ID,
владельца (ник, если загружен, и ID), число участников вместе с ботами,
дату присоединения бота по московскому времени и включённые права бота.
Если данные не загружены, выводится «неизвестно». Права перечислены на уровне
сервера; настройки отдельных каналов могут их изменять. Право `administrator`
даёт полный доступ независимо от остальных перечисленных флагов.

Просмотр: `docker compose logs --tail=200 brodyaga-bot`.
Это текущий список установок на момент вывода, а не статистика использования:
число участников сервера не равно числу пользователей бота.

Бот использует SQLite. Новые таблицы создаются автоматически при запуске без удаления существующих данных.

### `users`
- `user_id` — Discord ID пользователя
- `username` — Имя пользователя
- `registration_date` — Дата регистрации

### `trader_reports`
- `id` — ID записи
- `server` — Сервер (cherno-1/2/3/4)
- `location_name` — Название локации
- `x_coord`, `y_coord` — Координаты
- `reporter_id` — ID сообщившего пользователя
- `report_date` — Дата сообщения
- `is_first_reporter` — Флаг первого сообщившего

### `trader_history`
- Те же поля, что и в `trader_reports` + `archived_at` (дата архивирования)

### `location_checks`
- `server`, `location_name` — проверенная точка
- `checker_id` — Discord ID проверившего игрока
- `checked_at` — время проверки
- `status` — текущий статус (`not_found`)

### Таблицы подписок
- `server_subscriptions` — выбранные серверы для каждого Discord User ID.
- `trader_notification_events` — уже обработанные пары сервер/локация за текущий цикл, для защиты от повторных рассылок.
- `trader_notifications` — очередь личных уведомлений, статусы отправки и число попыток.

## ⚙️ Настройка

### Изменение времени архивирования

Граница периода поиска задаётся в `database.py`, в функции `_cycle_start`:

```python
boundary = now.replace(hour=1, minute=0, second=0, microsecond=0)
```

`01:00 UTC` соответствует `04:00 МСК`. Проверка выполняется при запуске, раз в минуту и при операциях с текущими отметками. Состояние периода сохраняется в таблице `bot_state`; сброс выполняется атомарно и однократно даже при одновременной работе бота и API.

### Добавление новых серверов

В `coords_handler.py` измените список `SERVERS`:

```python
SERVERS = ["cherno-1", "cherno-2", "cherno-3", "cherno-4", "cherno-5"]
```

## 🐛 Решение проблем

### Бот не запускается
- Убедитесь, что токен правильный в файле `.env`
- Проверьте логи: `docker compose logs`

### Бот не отвечает на команды
- Проверьте, что бот добавлен на сервер с правильными разрешениями
- Убедитесь, что включены MESSAGE CONTENT INTENT и SERVER MEMBERS INTENT

### Ошибки с базой данных
- Остановите бот: `docker compose down`
- Удалите `bot_database.db` — он создастся заново при запуске
